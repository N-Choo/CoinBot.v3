# Dev & Release Workflow

## Release flow (digest-pinned prod images)

Production images are pinned by digest in `docker-compose.prod.yml`. That file
is generated by `make pin-images`; do not edit it by hand. `make prod` pulls
exactly those digests and never builds.

```text
branch -> PR -> CI -> merge to main -> CI (tests + smoke + push-arm)
       -> make pin-images TAG=<sha> -> commit lock file -> Pi: git pull && make prod
```

### 1. Ship the code

Work on a branch, open a PR, and let CI run (`validate`, `backend-test`,
`frontend-test`). Merge to `main` when green.

### 2. Wait for the main CI run

The main run runs tests + smoke, then `push-arm` builds and pushes the
**changed** images as `ghcr.io/<owner>/coinbot-*:latest` and `:${github.sha}`.
Unchanged services are not rebuilt and keep their previous digest.

Do not pin until `push-arm` for that commit has finished.

### 3. Pin the build

On your dev machine, in the repo root:

```sh
git checkout main && git pull
TAG=$(git rev-parse HEAD)
make pin-images TAG="$TAG"
git diff -- docker-compose.prod.yml
```

`make pin-images` only queries GHCR with `docker buildx imagetools inspect`; it
does not build or start anything. Re-running it with no new images prints
`No image changes.`

Use `TAG=<sha>` (the commit CI built), not `TAG=latest`, so a concurrent merge
cannot pin a different build. If a changed-image build did not run for a
service, the script keeps that service's existing digest and prints
`not found; keeping existing pin`.

### 4. Commit the lock file

If `main` allows direct pushes:

```sh
git add docker-compose.prod.yml
git commit -m "release: pin images $(git rev-parse --short HEAD)"
git push
```

If `main` is protected (recommended), open a PR instead:

```sh
git checkout -b "release/pin-$(git rev-parse --short HEAD)"
make pin-images TAG=$(git rev-parse HEAD)
git add docker-compose.prod.yml
git commit -m "release: pin images"
git push -u origin HEAD
gh pr create --fill
```

Merge the PR. The pin commit triggers CI again, but `docker-compose.prod.yml`
is not in the image path filters, so `push-arm` does not rebuild images.

### 5. Deploy on the Pi

Before the first deploy, the Pi needs two untracked env files:

- **root `.env`** with the shared runtime config (`DATABASE_URL`,
  `GRPC_DEPOSIT_ENDPOINT`, `GRPC_TRADE_ENGINE_ENDPOINT`, `OPENCODE_BASE_URL`,
  `GRPC_AUTH_TOKEN`, `POSTGRES_*`, `REDIS_*`, `KUCOIN_*`, `SIGNAL_GATEWAY_*`).
- **`process/opencode/.env`** with `OPENCODE_SERVER_PASSWORD` (must match
  `OPENCODE_PASSWORD` in the root `.env`) and `OPENCODE_GO_API_KEY`.

Set both to mode `600` (`chmod 600 .env process/opencode/.env`).

```sh
git pull
make prod
make log SERVICE=signal-gateway-prod
```

`make prod` runs:

```sh
docker compose --env-file .env \
  -f docker-compose.yml -f docker-compose.prod.yml \
  --profile prod --profile tools pull
docker compose --env-file .env \
  -f docker-compose.yml -f docker-compose.prod.yml \
  --profile prod --profile tools up -d --no-build
```

First deploy creates the `signal_gateway_state` volume. With
`SIGNAL_GATEWAY_RUN_ON_START=false`, signal-gateway waits for the next 4h candle
close; set it to `true` in `.env` for an immediate run.

### Rollback

```sh
git revert <release commit>          # or: git checkout HEAD~1 -- docker-compose.prod.yml
make prod
```

### Notes

- `make prod-build` still builds `:latest` from `docker-compose.yml` for local
  testing. `make prod` ignores those images because it pulls by digest and uses
  `--no-build`.
- `make log` follows prod logs; `make log SERVICE=<name>` filters one service.
- Action SHAs in `.github/workflows/*.yml` (`uses: owner/action@<sha> # vN`) are
  pinned action versions, unrelated to image digests. They only change when you
  upgrade an action.
- `make pin-images` needs Docker with buildx and read access to GHCR (the
  images are public, so no login is required).
- Compose memory limits total roughly 7 GB (opencode alone is 2 GB). If the Pi
  has less RAM, lower the `mem_limit` values in `docker-compose.yml` or raise
  the host capacity; limits are ceilings, not reservations.
- `make test` publishes `127.0.0.1:5432` and `:6379` for host-side tests. Stop
  `make dev` first if those ports are already bound.
