# analyzer-rs

Rust port of the RSI-divergence analyzer. Phase 1 is the pure core.

```bash
make analyzer-rs-check
```

Parity fixtures are generated by the development-only oracle scripts under
`process/analyzer/tools/parity/` (no Python lives in this crate). Regenerate them only in the
exact environment pinned by `process/analyzer/requirements-oracle.txt`. Run from
`process/analyzer`:

```bash
.venv/bin/python tools/parity/synthetic.py \
  --out ../analyzer-rs/tests/fixtures/synthetic_1day.csv
.venv/bin/python tools/parity/emit.py \
  --data ../analyzer-rs/tests/fixtures/synthetic_1day.csv \
  --symbol SYNTH-USDT \
  --out ../analyzer-rs/tests/parity/synthetic_1day.json
```

The core has no I/O, no clock, and no floats. See
`docs/superpowers/specs/2026-10-21-rust-analyzer-migration-design.md`.

## Live gRPC client

Like `process/strategy-analyzer`, the trade engine is the gRPC server and the analyzer is the
client. The analyzer polls `GetActiveSymbols` for activation, runs one task per active symbol,
warms a rolling window, recomputes `signals()` on every newly closed candle, and publishes each
new signal once via `Publish`. Each signal gets exactly one publish attempt; nothing is resent
after a restart.

The same crate-local `.env` holds both strategy and live settings. It is loaded from the current
directory first, then from `process/analyzer-rs/.env` for `cargo run`. The file is gitignored, so
start from the checked-in example:

```bash
cp process/analyzer-rs/.env.example process/analyzer-rs/.env
# edit .env
cargo run -p analyzer-rs --features grpc --bin analyzer-serve
```

Existing process environment variables still take precedence over `.env` values. `LIVE_SYMBOLS`
is only a fallback: it is used when the engine returns an empty active-symbol set (or when the
engine is unreachable and no symbol tasks are running). `ANALYZER_ACTIVATION_POLL_MS` controls how
often activation is refreshed (default 30000).

`ANALYZER_ONCE=1` runs one closed-candle scan per symbol using the engine's active symbols (or
`LIVE_SYMBOLS` as the fallback), logs the signals, and exits:

```bash
ANALYZER_ONCE=1 \
GRPC_TRADE_ENGINE_ENDPOINT=http://127.0.0.1:50051 \
LIVE_SYMBOLS=BTC-USDT KUCOIN_TIMEFRAME=15min \
cargo run -p analyzer-rs --features grpc --bin analyzer-serve
```

## Replay report

`analyzer-replay` replays closed candles through the same signal engine and trade simulator used
by the parity tests, then writes a self-contained HTML report (no external CSS, JS, or network
references). Fees and slippage are excluded: the output is a signal/execution replay, not a
profitability claim. The report carries that label in its banner.

```bash
# Online: fetch candles from KuCoin and use BENCHMARK_TICKERS
make analyzer-replay ARGS='--timeframe 1day --limit 500'

# Offline: repeated --data SYMBOL=path entries; symbols default to these entries
cargo run -p analyzer-rs --features harness --bin analyzer-replay -- \
  --timeframe 1day \
  --data BTC-USDT=process/analyzer-rs/tests/fixtures/btc_usdt_1day.csv \
  --data XRP-USDT=process/analyzer-rs/tests/fixtures/xrp_usdt_1day.csv \
  --out /tmp/replay.html
```

Options:

- `--symbol SYMBOL` (repeatable) selects symbols explicitly. When omitted, the symbols from the
  `--data` entries are used; if there are none, `BENCHMARK_TICKERS` is used.
- `--data SYMBOL=path` loads a CSV instead of calling KuCoin. Paths are resolved from the current
  working directory.
- `--timeframe` falls back to `KUCOIN_TIMEFRAME`, then `15min`.
- `--limit` (default 500) is appended to the strategy warmup window when fetching.
- `--init-fund` falls back to `BENCHMARK_INIT_FUND`, then `1000`.
- `--as-of` is the reference time in milliseconds. It defaults to now, so only closed candles are
  replayed; pass a fixed timestamp for deterministic runs.
- `--generated-at` overrides the report timestamp.
- `--max-gap-candles` (default 0, must be `>= 0`) rejects datasets with larger gaps.
- `--out` defaults to `process/analyzer-rs/out/replay.html`.

The remaining strategy settings (`RSI_*`, `SMA_*`, `ATR_*`, `PRICE_DIFF_THRESHOLD`,
`ANALYZER_WINDOW_CANDLES`) and `ANALYZER_MAX_DIVERGENCE_AGE_CANDLES` come from the same `.env`
as the live client; see `.env.example`. `KUCOIN_BASE_URL` overrides the exchange endpoint.
